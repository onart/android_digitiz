# Digitiz

안드로이드 폰을 PC의 **디지타이저(펜 태블릿)** 로 쓴다.
폰 화면을 터치하면 PC에서 클릭이, 슬라이드하면 드래그가 발생한다.

- **PC = 호스트(서버)** — 좌표를 받아 OS에 마우스 입력으로 주입
- **Android = 게스트(클라이언트)** — 터치를 PC 좌표로 변환해 전송
- **연결 = USB 유선**, ADB reverse TCP 터널

## 현재 상태

1차 마일스톤 진행 중.

- [x] Phase 0 — 리포/툴체인
- [x] Phase 1 — `common/` (프로토콜, Framer, 좌표변환, 로그)
- [x] Phase 2 — 호스트 골격 (ImGui 셸, 화면 정보, 입력 주입, 포인터 파이프라인)
- [x] Phase 3 — ADB 전송 (reverse 터널, 세션 루프, PING/PONG)
- [x] Phase 4 — 게스트 (GameActivity + GLES3, 그리드, 핀치, 터치 라우팅, 사이드 메뉴)
- [x] Phase 5 — 통합 (지연 측정, 재연결/백그라운드 처리, 세팅 가이드)

**1차 마일스톤 완료.** 실측 지연: PING/PONG 왕복 1.6~4.2 ms, 터치 이벤트가
호스트에 도달하기까지 평균 11.3 ms, 주입은 측정 한계 이하.

## 처음 쓰는 법

**폰에서 (한 번만)**

1. 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호를 7번 탭** (개발자 옵션 활성화)
2. 설정 → 개발자 옵션 → **USB 디버깅** 켜기
3. USB 케이블로 PC에 연결
4. 폰에 뜨는 **"USB 디버깅을 허용하시겠습니까?"** 에서 「이 컴퓨터에서 항상 허용」 체크 후 허용

**PC에서**

```bash
adb devices          # 폰이 device 상태로 보이면 준비 완료
digitiz_host.exe
```

호스트가 알아서 터널을 세우고 폰의 앱을 실행한 뒤 접속을 기다린다.
앱을 미리 설치해 두어야 한다 (`./tools/guest.sh install`).

마지막으로 호스트 창에서 **INJECTION 토글을 켜야** 폰 터치가 PC에 전달된다.
꺼져 있을 때는 좌표를 받아 세기만 하고 주입하지 않는다.

**폰 화면 읽는 법** — 그리드 색이 상태 표시다.

| 색 | 뜻 |
|---|---|
| 회색 | 호스트와 연결되지 않음 |
| 호박색 | 연결됨, 주입은 꺼짐 |
| 초록색 | 입력이 실제로 PC에 전달되는 중 |

주황색 사각형은 PC 화면들의 경계다. 멀티모니터면 **모니터마다 하나씩** 그려진다.
그 바깥은 그리드가 흐려지고 **터치해도 아무 일도 일어나지 않는다** — 가장 가까운
화면 가장자리로 커서를 끌고 가는 대신, 누른 적 없는 곳으로 커서가 튀지 않도록
그냥 무시한다.

모니터 크기가 다르면 경계 사각형들 사이에 어디에도 속하지 않는 구석이 생긴다.
그 구석도 똑같이 죽은 영역이고, 미니맵에도 그렇게 보인다.
획을 긋다가 죽은 영역을 지나가면 커서는 마지막 유효 지점에 머물다가 다시 화면
위로 들어오면 이어진다 — 획이 끊기지 않는다.

**입력 모드** — 우측 엣지 핸들을 탭하면 사이드 메뉴가 열리고 두 모드를 고를 수 있다.
현재 모드는 **핸들 자체에 표시**되므로 메뉴를 열지 않아도 알 수 있다.

| 모드 | 핸들 표시 | 한 손가락 | 두 손가락 이상 |
|---|---|---|---|
| **그리기** (기본) | 초록 점 | 화면과 1:1로 대응해 그린다 | 확대·이동 |
| **슬라이딩** | 초록 노브 | 커서를 현재 위치에서 상대 이동, 짧은 탭은 클릭 | 감도 조절 |
| **화면 이동** | 흰 십자 | 확대·이동 | 확대·이동 |

그리기 모드에서 그리는 도중 두 번째 손가락이 닿으면 그 획은 취소되고 PC의 버튼이
떨어진다. 화면 이동 모드에서는 PC로 아무것도 보내지 않으므로, 엄지 하나로 뷰를
맞추는 동안 실수로 획이 그어질 일이 없다.

**슬라이딩**은 트랙패드처럼 동작한다. 절대 좌표를 버리고 축척만 남기므로, 손가락을
떼고 아무 데나 다시 짚어도 커서가 튀지 않고 작은 화면으로 넓은 데스크톱을 다 덮는다.
축척이 곧 감도라, 확대하면 정밀해지고 축소하면 광역이 된다. 절대 기준이 없으니
화면 경계선과 미니맵은 이 모드에서 숨는다 — 가리킬 곳이 없는 것을 그려두면
오해만 부르기 때문이다.

**곡선 보정** — 호스트 창의 *Curve smoothing*. 도착한 샘플 사이를 Catmull-Rom
곡선으로 채워, 획이 꺾인 선이 아니라 곡선으로 그려지게 한다. 아래 최소 간격과 짝으로
쓴다 — 솎아낸 점을 이쪽이 다시 메운다.

**한 샘플만큼 지연이 생기고 이건 없앨 수 없다.** 어떤 점을 지나는 곡선은 그 다음
점이 도착해야 정해지기 때문이다. 그리는 동안 커서가 손가락을 한 박자 뒤따르고,
획을 놓는 순간 따라잡는다. 그래서 옵션이며, 창에 실측 지연량이 표시된다.
슬라이딩 모드에는 적용하지 않는다.

**최소 간격** — 사이드 메뉴의 슬라이더 둘. 그리기 모드에서 좌표를 보내는 빈도를
시간(0~40 ms)과 거리(0~16 dp)로 각각 제한한다. **둘 다 만족해야** 전송되므로,
느린 손놀림은 거리가 채워질 때까지, 빠른 손놀림은 시간이 찰 때까지 기다린다.

이건 점을 **솎아낼 뿐 그 자체로 곡선을 부드럽게 하지는 않는다.** 고르게 벌어진
점을 호스트의 스플라인 보정에 먹이는 것이 목적이라, 두 기능은 짝으로 쓴다.
슬라이딩 모드에는 적용하지 않는다 — 포인팅이 끊겨 보이면 곤란하기 때문이다.

**자동 실행** — 사이드 메뉴의 스위치. 켜져 있으면 호스트가 기기를 발견할 때 앱을
대신 띄운다. 끄면 직접 열 때까지 기다린다 (터널은 유지되므로 열자마자 연결된다).

설정은 **폰에 저장된다** — 호스트는 실행 여부를 앱이 꺼져 있을 때 알아야 하므로
링크로 물어볼 수 없고, 대신 `adb` 로 폰의 파일을 직접 읽는다:

```
/sdcard/Android/data/com.onart.digitiz/files/settings.txt
```

**종료** — 뒤로가기를 누르면 확인 토스트가 뜨고, 2초 안에 한 번 더 누르면 종료된다.
그리는 도중 뒤로가기가 한 번 스쳤다고 연결이 끊기면 곤란하기 때문이다.

**커스텀 버튼** — 화면 가장자리의 스트립. 얇은 탭을 누르면 펴지고, `+` 로 추가한다.
버튼을 **길게 누르면** 편집·순서 이동·삭제 메뉴가 뜬다. 세 종류가 있다.

| 종류 | 입력하는 값 | 누르면 |
|---|---|---|
| 좌표 | `x, y` | 그 자리를 클릭 |
| 단축키 | `ctrl+shift+s` | 그 키 조합을 PC에 보낸다 |

좌표는 **데스크톱이 아니라 활성 창 기준**이다. 창을 옮기거나 다른 모니터에서
열어도 버튼이 같은 것을 가리킨다. 숫자는 **호스트 창의 `Cursor:` 줄**에서 읽는다 —
PC에서 원하는 지점에 마우스를 올리면 그 창 안에서의 좌표가 표시된다
(`Copy` 버튼도 있다).

**버튼 표시 개수**는 사이드 메뉴의 슬라이더로 정한다. 기본값은 해당 방향 길이의
절반에 들어가는 만큼이고 — 그리는 면 위의 오버레이가 기본으로 화면을 가로지르면
곤란하다 — 최대는 화면이 감당하는 만큼이다. 방향을 바꾸면 그쪽 최대에 맞춰 잘린다.

들어갈 자리보다 버튼이 많으면 **스트립 방향으로 끌어서** 넘긴다. 양 끝의 점은
한 칸씩 움직이는 용도로 남아 있다. 끝에서 멈추지 않고 순환한다. 가로(아래
가장자리)와 세로(왼쪽 가장자리)는 사이드 메뉴 헤더의 막대 글리프 버튼으로
바꾼다. 방향과 접힘 상태는 폰에 저장된다.

버튼 목록도 폰에 있다. 탭으로 구분된 한 줄에 버튼 하나라 그냥 읽힌다:

```
/sdcard/Android/data/com.onart.digitiz/files/buttons.txt
```

**프리셋** — 버튼 묶음에 이름을 붙인 것. 스트립의 **탭을 길게 누르면** 목록이
뜬다: 전환, 새로 만들기, 이름 변경, 활성 창에 연결, 연결 해제, 삭제.

프로그램에 연결해두면, PC에서 그 프로그램이 활성화될 때 스트립 옆에 `✓ ✕` 가
뜬다. **자동으로 바뀌지는 않는다** — 원하는 창까지 가는 동안 포커스가 여러 창을
스쳐 가는데 그때마다 버튼이 통째로 바뀌면 못 쓰기 때문이다. 모달도 아니라서
무시하고 계속 그려도 된다. `✕` 로 거절하면 그 프로그램에 대해서는 다시 묻지
않고, 다른 프로그램에 갔다 오면 다시 묻는다.

스트립 옆 캡션은 **지금 PC에서 포커스를 가진 프로그램 / 지금 쓰는 프리셋**을
보여준다. "왜 이 버튼들인가"의 답이다.

**PC 화면 표시** — 사이드 메뉴 헤더의 모니터 글리프 버튼. 켜면 지금 보고 있는
영역의 PC 화면이 그리는 면에 그려진다. **기본은 꺼짐** — 포인터가 쓰는 링크의
대역폭을 나눠 쓰는 유일한 설정이라, 켜져 있는 것을 발견하기보다 직접 켜는 쪽이
낫다.

바뀐 곳만, 그것도 프레임당 정해진 양만 보낸다. 그래서 화면이 크게 바뀌면 한 번에
갈아치우는 대신 몇 프레임에 걸쳐 채워진다. 대신 대역폭이 절벽처럼 끊기지 않고
입력이 뒤에 밀리지 않는다 — 스트로크 지연은 켜나 끄나 측정 차이가 없다.

핀치나 팬으로 보는 곳을 바꾸면 **멈춘 뒤** 새 영역을 요청한다. 움직이는 동안
요청하면 전송이 계속 처음부터 다시 시작해 한 번도 끝나지 않기 때문이다.
슬라이딩 모드에서는 가리킬 절대 영역이 없으므로 꺼진다.

**미니맵** — 확대해서 PC 화면 경계가 화면 밖으로 나가면 좌상단에 미니맵이 나타나
전체 중 어느 부분을 보고 있는지 알려준다. 경계가 다 보이면 사라진다.
정보 표시일 뿐이라 **터치를 가로채지 않는다** — 그리는 면 위에 획을 삼키는 영역이
생기는 편이 조금 가려지는 것보다 나쁘기 때문이다.
PC 화면을 켜면 화면 자체가 같은 답을 더 잘 주므로 미니맵은 숨는다.
버튼 스트립을 세로로 두면 미니맵이 그만큼 오른쪽으로 밀린다.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 호스트가 `Unauthorized` | 폰의 RSA 허용 대화상자를 수락한다. 케이블을 다시 꽂거나 재부팅하면 다시 물어볼 수 있다 |
| 호스트가 `Waiting for device` 에서 멈춤 | `adb devices` 로 확인. 비어 있으면 USB 디버깅이 꺼졌거나 OEM 드라이버가 필요하다 |
| `No adb` | adb를 PATH에 두거나 `ANDROID_HOME` 을 설정한다 |
| 다른 프로그램의 adb 연결이 끊김 | adb 서버는 5037 포트에 하나뿐이라 버전이 다르면 서로 재시작시킨다. 호스트는 PATH의 adb를 먼저 쓰므로, Android Studio와 같은 adb를 PATH에 두면 충돌하지 않는다 |
| 특정 창에서만 클릭이 안 먹음 | 관리자 권한으로 실행 중인 창에는 주입할 수 없다(UIPI). 호스트도 관리자로 실행해야 한다 |
| 커서가 엉뚱한 곳으로 감 | 호스트의 **Self-test → coordinate accuracy sweep** 을 돌려본다. 0.00 px 가 정상이다 |

## 실행

```bash
./build/debug/host/digitiz_host.exe
```

전송 계층 없이도 동작한다. 창에는 주입 on/off 토글, 모니터 목록, 파이프라인 통계,
콘솔이 있고 **Self-test** 섹션에서 폰 없이 입력 주입을 검증할 수 있다.

폰이 USB로 연결돼 있고 USB 디버깅이 켜져 있으면 자동으로 reverse 터널을 세우고
게스트 앱을 실행한 뒤 접속을 기다린다. 게스트가 아직 없어도 문제없이 대기한다.

좌표 정확도 검사는 헤드리스로도 돌아간다 (커서를 25지점 훑고 원위치, 클릭 없음):

```bash
./build/debug/host/digitiz_host.exe --selftest
```

게스트 앱 없이 터널 전 구간을 확인하려면 (디바이스의 netcat을 씀):

```bash
./tools/test-tunnel.sh
```

## 빌드 (PC)

```bash
cmake --preset release && cmake --build --preset release && ctest --preset release
```

**릴리스가 기본이다.** 이 프로그램은 인코딩이 프레임 예산을 정하는 종류라 최적화가
기능에 직접 들어온다 — ETC2 인코딩이 Debug에서 타일당 4 ms, Release에서 **0.7 ms**다.
Debug로 재고 있으면 한 번에 보낼 수 있는 타일 수를 다섯 배 낮게 잡게 된다.
`debug` 프리셋도 있고 디버거를 붙일 때 쓰면 된다.

### Windows 주의

Ninja + MSVC 조합은 **컴파일러 환경이 셋업된 셸**을 요구한다.
"Developer Command Prompt for VS" 에서 실행하거나, 일반 셸이라면 먼저:

```bat
"C:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat"
```

**Git Bash에서 `cmd //c "... && cmake --build ..."` 로 우회하지 말 것.** 경로가
깨져서 `지정된 경로를 찾을 수 없습니다` 하나만 남기고 조용히 실패하는데, 빌드가
안 돌았다는 사실이 드러나지 않아 **낡은 바이너리로 존재하지도 않는 버그를 쫓게
된다.** 실제로 그러다 하트비트 버그를 한참 헤맸다. PowerShell이나 Developer
Command Prompt에서 돌리고, 의심스러우면 exe의 타임스탬프를 확인한다.

`Visual Studio` 제너레이터를 쓰지 않는 이유: 이 개발 환경에는 VS 18 Community가
설치돼 있는데 CMake 3.30에는 VS 18 제너레이터가 없다. CMake를 올리면 쓸 수 있지만
Ninja가 어차피 더 빠르고 크로스플랫폼이라 그대로 간다.

## 빌드 (Android)

```bash
./tools/guest.sh run      # 빌드 → 설치 → 실행 → 로그 tail
```

`build` / `install` / `log` 하위 명령도 있다. NDK r27 (`27.3.13750724`),
compileSdk 35, minSdk 24가 필요하다.

이 스크립트가 존재하는 이유는 이 개발 환경의 함정 두 개 때문이다.
`JAVA_HOME` 이 emsdk의 Java 8을 가리켜서 Gradle이 거부하고(Android Studio 번들
JBR 17로 덮어쓴다), Git Bash가 `/data/...` 인자를 Windows 경로로 바꿔버린다.

Android Studio로 열려면 `guest/` 를 프로젝트 루트로 연다. `local.properties` 는
gitignore 되어 있으므로 각자 만들어야 한다 (`sdk.dir=C:/path/to/Sdk`,
**백슬래시 금지** — Java Properties가 `\U` 를 유니코드 이스케이프로 읽는다).

## 레이아웃

```
common/   호스트·게스트 공유 C++. 플랫폼 헤더 금지 — 표준 라이브러리만
host/     PC 호스트 (Phase 2)
guest/    Android 게스트 (Phase 4)
docs/     설계 문서
```

게스트는 Gradle이 빌드하지만, 안드로이드에 의존하지 않는 부분(버튼 저장 등)은
`guest/tests/` 에서 데스크톱 CMake가 같이 빌드해 폰 없이 테스트한다.
`ctest` 는 `common`, `host`, `guest` 세 묶음을 돌린다.

`common/` 은 데스크톱 CMake와 안드로이드 CMake 양쪽에서 그대로 빌드된다.
그래서 저기에는 `<windows.h>` 도, `<android/*.h>` 도, 소켓 API도 들어가지 않는다.
