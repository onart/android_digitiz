# 구현 계획

## 1차 마일스톤 (최소사양)

목표: **폰을 터치하면 PC에서 클릭되고, 슬라이드하면 드래그된다.**
게스트는 PC 절대 픽셀에 대응하는 그리드 + 핀치 조정 + 빈 사이드 메뉴.
호스트는 중계 + on/off + 콘솔 로거.

### 순서 원칙

ADB 전송으로 확정하면서 **프로젝트-킬러급 리스크는 사라졌다.**
남은 순서 원칙은 두 가지다.

1. **작업 10(입력 주입)을 단독 검증 가능하게 만든다.** 나중에 "클릭이 안 된다"가
   주입 문제인지 전송 문제인지 즉시 갈라진다.
2. **작업 3(폰에서 빈 앱 실행)과 작업 12(adb 기기 인식)를 Phase 0에서 확인한다.**
   기기·OEM별 드라이버 이슈(R3)는 있어도 조기에 드러나는 편이 낫다.

1픽셀 틀려 있었고, `--selftest` 의 실측(반올림 1.00 px vs 올림 0.00 px)이

중복 DOWN, DOWN 없는 UP, 버튼이 어긋난 UP, 스트로크 도중 비활성화, 세션 강제 종료.
사용자 PC의 마우스가 눌린 채 남는 게 이 프로그램 최악의 실패 모드다.

**호스트 측 포트는 임시 포트(bind 0)** 로 잡는다. 디바이스 측만 27183으로 고정하면

`TCP_NODELAY` 를 빠뜨리면 Nagle이 포인터 이벤트를 뭉쳐 원인 찾기 어려운 지연이
생긴다. 세션 수립 직후 설정한다.

### Phase 4에서 걸린 것들

빌드 셋업이 구현보다 오래 걸렸다. 재발 방지를 위해 기록한다.

- `games-activity` 3.0.5는 **POM에 의존성을 선언하지 않는데** `GameActivity`는
  `AppCompatActivity`를 상속한다 → `androidx.appcompat` 직접 추가 + 테마도
  `Theme.AppCompat` 계열이어야 함
- 그 결과 kotlin-stdlib 중복 클래스 → jdk7/jdk8 아티팩트를 1.8 이상으로 제약
- JNI 심볼이 링커에 제거됨 → `--whole-archive` 필요
- `local.properties`에 백슬래시 금지 (Java Properties의 `\u` 이스케이프)
- **Android 15의 16KB 페이지**: 정렬 안 되면 시스템 경고 다이얼로그가 앱을 덮고
  포커스를 뺏는다 → `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`
- 메인 루프에서 poll 타임아웃을 루프 밖에서 한 번만 정하면, 포커스를 잃는 순간
  영원히 블록된다 (복귀 명령이 루프 안에서 오기 때문) → 매 반복 재계산

### Phase 4 검증 방법

실기에 손을 대지 않고도 전 구간을 확인할 수 있다.

```bash
adb exec-out screencap -p > screen.png     # 렌더링 확인
adb shell input swipe 150 550 500 800 500  # 스트로크 주입
```

720x1544 화면에서 1920x1080 데스크톱에 맞춘 상태(scale 0.33)로
`(150,550) → (500,800)` 을 그으면 호스트가 `DOWN (455, 148)` / `UP (1515, 906)` 을
받아야 한다. 계산값과 실측값이 일치하는지가 좌표계 전체의 검증이다.

### Phase 5 — 통합

| # | 작업 | 상태 |
|---|---|---|
| 23 | 종단 지연 측정 (클럭 오프셋 추정 + 롤링 통계 + UI 표시) | ✅ |
| 24 | 연결 해제 · 재연결 · 백그라운드 복귀 처리 | ✅ |

**측정 결과** (Galaxy S23 Ultra, HD+ 720x1544, USB 2.0)

| 구간 | 값 |
|---|---|
| PING/PONG 왕복 | 1.6 ~ 4.2 ms |
| 이벤트 → 호스트 도달 | 평균 11.3 ms, 최대 20.8 ms |
| `SendInput` 주입 | 측정 한계 이하 (수 µs) |

"이벤트 → 호스트"는 안드로이드가 터치에 찍은 타임스탬프 기준이므로
**터치스크린 스캔 지연은 포함되지 않는다.** 실제 손가락→커서는 이보다 높다.

두 클럭은 epoch가 다르므로 오프셋을 측정해야 한다. PONG 왕복 중 **가장 빠른**
것으로 추정한다 — 빠른 왕복은 대칭에 가깝지만 느린 왕복은 어느 쪽 다리에서
지연됐는지 알 수 없어 평균을 내면 오히려 틀어진다.

### Phase 5에서 드러난 것들

실기 생명주기 테스트가 아니었으면 못 잡았을 것들이다.

- **`GameActivityMotionEvent::eventTime` 은 나노초가 아니라 밀리초다.**
  기저 `AMotionEvent` API는 나노초라 헤더만 보면 틀리기 쉽다. 단위가 틀려도
  아무것도 실패하지 않고 지연 수치만 조용히 버려진다 → 런타임 정합성 검사를
  `TouchRouter::emit()` 에 상시 남겨뒀다
- **게스트에 수신 타임아웃이 없었다.** 호스트가 비정상 종료하면 adb가 터널을
  남기고, 소켓이 조용해질 뿐 닫히지 않는 경우가 있다 → 5초 무음이면 재연결
- **호스트가 꺼져 있을 때 재연결 루프가 시끄러웠다.** adb는 PC쪽에 아무도 없어도
  기기 쪽 연결을 받아주므로 `connect()` 는 성공하고 2초 뒤 끊긴다. 세션 성립
  판정을 시간이 아니라 **"호스트가 한 바이트라도 보냈는가"** 로 바꿨다
  (adb의 포기 지연이 하필 임계값 근처에 있어 시간 기준은 취약하다)
- **백그라운드 복귀 시 뷰가 초기화되던 문제.** 사용자가 맞춰둔 확대·이동이
  사라졌다 → 최초 1회와 데스크톱 구성 변경 시에만 다시 맞춘다
- **`tools/guest.sh` 가 호출자의 `MSYS_NO_PATHCONV` 를 상속받아** `adb install` 이
  조용히 실패했다. 설치되지도 않은 코드의 버그를 한참 쫓았다 → 스크립트가 해당
  변수를 `unset` 하고, 설치 후 **기기 APK의 md5를 빌드 산출물과 대조**한다

### 1차 이후 추가된 것

써보고 나서 필요하다고 판단되어 1차 범위 밖에서 추가한 항목들.

- **가로모드 고정** — PC 데스크톱이 가로라 세로 화면은 면적을 크게 낭비했다.
  1920x1080 기준 축척 0.33 → 0.59
- **입력 모드 토글** (사이드 메뉴) — Draw / Pan. Pan 모드는 한 손가락으로 뷰만
  움직이고 PC에는 아무것도 보내지 않는다. 현재 모드는 엣지 핸들에 표시되므로
  메뉴를 열지 않아도 "이 손가락이 PC에 그려지는가"를 알 수 있다
- **텍스트 렌더링** — 안드로이드 `Paint` → GL 텍스처. 설정이 둘을 넘어가면서
  그림만으로는 설명이 안 됐다. 폰트 번들 대신 플랫폼에 맡겨 한글을 공짜로 얻고,
  라벨은 `strings.xml` 에서 읽어 `values-ko` 가 그대로 적용된다
- **미니맵** — 확대해서 데스크톱 경계가 화면 밖으로 나갔을 때만 좌상단에 표시.
  **터치를 가로채지 않는다**: 그리는 면에 획을 삼키는 영역을 만드는 건
  조금 가려지는 것보다 나쁘다. 2차에서 화면 전송이 붙으면 숨긴다

### 슬라이딩 모드

지금의 Draw는 폰 표면과 PC 좌표가 1:1인 **절대** 매핑이다. 슬라이딩 모드는
축척만 남기고, 어디서 터치를 시작하든 **커서의 현재 위치에서** 그 움직임을
따라간다. 태블릿의 펜 모드 / 마우스 모드 구분과 같다.

절대는 그리기에 맞고, 상대는 일반적인 포인팅에 맞다 — 손가락을 떼고 다시 짚어도
커서가 튀지 않고, 작은 화면으로 넓은 데스크톱을 다 덮을 수 있다.

**커서 위치는 호스트가 소유한다.** 게스트는 커서가 어디 있는지 모르므로 와이어에는
델타가 흐른다. `Pointer` 의 `flags` 바이트가 비어 있으니 `bit0 = 상대 좌표` 로
정의하면 메시지도 파이프라인도 그대로 쓴다.

구현 시 놓치기 쉬운 것들:

- **매 `DOWN` 마다 `GetCursorPos()` 로 다시 읽어야 한다.** 스트로크 사이에 사용자가
  실제 마우스를 움직였을 수 있고, 내부 누산기만 믿으면 커서가 순간이동한다
- **누적은 부동소수로.** 축척 0.5배에서 1px 델타는 0.5px이고, 정수로 자르면 느린
  움직임이 아예 전달되지 않는다. 싸구려 트랙패드가 끈적한 이유가 이것이다
- **절대 기준 UI를 꺼야 한다.** 데스크톱 경계선과 미니맵은 상대 모드에서 아무것도
  의미하지 않으므로 그대로 두면 오해를 부른다. 화면 밖 입력 차단도 해당 없음
  (밖이라는 게 없다)
- **가장자리 클램프는 누산기까지.** 위치만 클램프하면 되돌아올 때 밀어낸 만큼
  헛돈다. 멀티모니터에서 어느 화면으로 넘어갈지도 규칙이 필요하다
- 핀치는 위치 조정에서 **감도 조정**으로 의미가 바뀌고, 두 손가락 이동은 의미를 잃는다
- 모드가 셋이 되면 지금의 "탭하면 뒤집기" 행은 순환이나 목록으로 바꿔야 한다
- 화면 전송(절대 영역)과 상대 모드는 충돌한다. 상대 모드에서는 전송을 끄거나
  커서를 따라다니게 해야 한다 **(← 화면 전송 구현 시 남은 과제)**

**구현 결과.** 누름 여부는 모드가 정한다: 그리기는 펜(닿으면 누름), 슬라이딩은
트랙패드(닿으면 이동만, 짧은 탭이 클릭). "누르지 않고 이동"은 추가 비용이 거의
없었다 — 호스트 파이프라인이 `Down` 없는 `Move` 를 이미 버튼 없는 커서 이동으로
처리하고 있었다. 새로 든 건 탭 판정뿐이다.

소수점은 **게스트가** 누적한다. 축척을 아는 쪽이 거기이고, 와이어에는 정수 델타만
흐르므로 호스트는 더하기만 하면 된다. 실측: 표면 (+500, +200) 스와이프가 축척
0.5867에서 정확히 (852, 340) px로 전달됐다 (이론값 852.2, 340.9).

가장자리는 **축 분리 클램프**다. 한 쌍으로 거부되면 x만, 그다음 y만 시도한다.
대각선으로 모서리에 부딪혀도 가장자리를 따라 미끄러지고, 멀티모니터의 계단진
경계에서도 별도 규칙 없이 동작한다.

### M2의 지배적 제약

USB 2.0 실효 대역폭은 **20~35 MB/s** 수준이다 (전송 계층과 무관하게 USB가 상한).
1080p BGRA 30fps = 250 MB/s로 **한 자릿수 배 초과**.
따라서 화면 전송은 압축이 선택이 아니라 필수이며, 해상도 비율 옵션이
사용자가 조절할 수 있는 유일한 완충 장치다.

흐름 제어에서 **입력 지연은 화면 지연보다 항상 우선한다.**
프레임이 큐를 막아 포인터 이벤트가 밀리면 디지타이저로서 실격이다.
